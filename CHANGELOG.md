## [2.5.1] - 2026-10-25

### Added
- **Code of Conduct and citation metadata** (#130): `CODE_OF_CONDUCT.md` is the Contributor Covenant 2.1 (text under CC-BY-4.0, `LICENSES/CC-BY-4.0.txt`), with reports to pablitos1024@gmail.com; `CONTRIBUTING.md`, the README and the issue chooser link it. `CITATION.cff` (CFF 1.2.0) describes the current release for GitHub's *Cite this repository*.

The README and `docs/getting_started.md` (method 4) give installation from the registry (a `vcpkg-configuration.json` with a `git` registry) as the main vcpkg method; the overlay port stays as the alternative.

### Changed
- **File paths of the `.deb` and of the Linux `.tar.gz`** (#133): the release packages are built with the prefix `/usr` (`tools/package_linux.sh`, used by `release.yml`), so the library, its CMake package and the Qt Designer plugin are under the multiarch directory: `/usr/lib/x86_64-linux-gnu/libQtIndustrialWidgets.so*`, `/usr/lib/x86_64-linux-gnu/cmake/QtIndustrialWidgets/`, `/usr/lib/x86_64-linux-gnu/qt6/plugins/designer/QtIndustrialWidgetsPlugin.so` (before: `/usr/lib/…` and `/usr/lib/qt6/plugins/designer/`). The `.tar.gz` has the same layout (`lib/x86_64-linux-gnu/…`). Both packages are built and checked on Ubuntu 24.04. `find_package(QtIndustrialWidgets)` finds both layouts without changes.
- **Contact e-mail address** (#128): `pablitos1024@gmail.com` replaces the previous address in every file: SPDX headers and `.license` sidecars, `REUSE.toml`, the SBOM creator of `release.yml`, the CPack contact and Debian maintainer, the Conan `author`, `CONTRIBUTING.md`, `SECURITY.md` and the documentation. The vcpkg port changes with it (its SPDX comment and `vcpkg.json.license`), so it becomes `2.5.0` with `port-version` 1; the library is unchanged. The description of the vcpkg port, of `project()` and of the CPack packages (`.deb` summary) is now a short form of the README's opening sentence instead of "Modern, high-performance industrial instruments and SCADA widgets for Qt" (#124 rules).
- **Paint target of #5 withdrawn** (4 ch × 1M `BroadbandNoise` ≤ 8 ms per frame, steady-state median): the maintainer withdrew it on 2026-10-24, not met. The measured frame time (about 10 ms in the fast mode, 17–21 ms in the slow mode of the benchmark machine, `docs/benchmarks.md`) is judged sufficient. In `docs/benchmarks.md` the two #5 rows of the *Targets* table keep their measurements and their **FAIL**, with the withdrawal noted.
- **vcpkg port no longer marked experimental** (#66): the README and `docs/getting_started.md` say it is verified on Linux (`x64-linux-release`) by the packaging workflow, after the run with `port=released` on the `v2.5.0` port (release archive and SHA512). Windows and macOS are not verified yet.
- **vcpkg and Conan verified on Windows and macOS** (#66): the README and `docs/getting_started.md` (methods 4 and 5, note on a static Qt) say the vcpkg port (overlay and registry) is verified on Linux (`x64-linux-release`), Windows (`x64-windows-static-md-release`, `x64-windows-release`) and macOS (`arm64-osx-release`), and the Conan recipe on the same three systems with Qt from ConanCenter. Method 4 describes a dynamic triplet (DLLs next to the executable, Qt plugins loaded at run time); method 5 says that ConanCenter's Windows Qt binaries need `-s compiler.cppstd=17`.

### Fixed
- **`IndustrialSwitch`: the arrow keys moved the switch while the safety guard was closed** (#142): with the guard closed, Space and Return open it, as before, and every other key (Up, Down, Left, Right) is now ignored, as are drags and wheel steps. So no user input moves a guarded switch before the guard is opened, as `docs/widgets.md` states. `setPosition()`, `setChecked()` and `toggle()` called by the application are not affected.
- **API reference: seven classes had two pages** (#144): the class descriptions of `AnnunciatorPanel`, `IndustrialSwitch`, `LedIndicator`, `LevelMeter`, `LinearGauge`, `RadialGauge` and `SevenSegmentDisplay` came before `namespace QtIndustrialWidgets`, so Doxygen made a second class outside the namespace (`api/classLevelMeter.html`, …) that carried the description, while the namespaced page (with the members) had none. The comments are now inside the namespace, as in the other headers: each class has one page, with its description. The old addresses of the seven extra pages (`api/class<Name>.html` and, at the root, `class<Name>.html`) are now redirect stubs to the namespaced pages, written by `docs/site/assemble_site.cmake` and checked by `tools/check_site.py` (also with `--url`). The header changes are comments only: the exported symbols are unchanged.
- **API reference: class descriptions of the public headers** (#126): the Doxygen comments no longer use marketing wording ("high-performance", "realistic", "authentic", "heavy-duty", …), and the statements the code or `docs/benchmarks.md` contradicted are corrected: no "sub-millisecond rendering", no allocation-free claim beyond the measured appends, and no "bounded frame time" guarantee for `StripChart`. Other corrections:
  - `LevelMeter` has 2 channels by default, not 1;
  - peak decay is linear, not "ballistic";
  - `SevenSegmentDisplay` is not a drop-in `QLCDNumber` replacement, and `setText()` shows a fixed set of characters;
  - the `IndustrialSwitch` guard is not spring-loaded;
  - `Compass` computes the course deviation but draws no deviation indicator;
  - `AnnunciatorPanel`'s advisory colour is cyan;
  - `AnalysisChart` and `StripChart` can decimate the same data differently.
  Comments only: the exported symbols are unchanged.
- **Qt Designer did not find the plugin installed by the `.deb`** (#133): the package put it in `/usr/lib/qt6/plugins/designer/`, while Ubuntu's Qt scans `/usr/lib/x86_64-linux-gnu/qt6/plugins` (`qtpaths6 --plugin-dir`). It is now installed there, and the absolute entry of the plugin's run path is `/usr/lib/x86_64-linux-gnu` instead of the configure-time `/usr/local/lib`. **Known issue of the published v2.5.0 `.deb`** (not replaced): Qt Designer does not load its plugin; start Designer with `QT_PLUGIN_PATH=/usr/lib/qt6/plugins` (checked in CI on the release asset: its plugin has no run path, and the library is found in `/usr/lib`).
- **Installed Qt Designer plugin could not find the library** (#127): `cmake --install` wrote `QtIndustrialWidgetsPlugin` without a run path, so outside the loader's default directories (a prefix such as `/opt/QtIndustrialWidgets`, or the extracted `.tar.gz` of the release) Qt Designer could not load it (`libQtIndustrialWidgets.so.2: cannot open shared object file`) unless `LD_LIBRARY_PATH` was set. On Linux and macOS the installed plugin now has the run path `$ORIGIN/<plugin dir → lib dir>` (`@loader_path/…` on macOS), so a moved prefix works, followed by the absolute `CMAKE_INSTALL_FULL_LIBDIR`, for a plugin directory outside the prefix (`QT_INSTALL_PLUGINS`). `docs/designer_plugin.md` describes it, and says that on Windows `QtIndustrialWidgets.dll` must be on `PATH` or next to `designer.exe`.
- **Guides aligned with the code** (#124): `docs/theming.md`, `docs/getting_started.md`, `docs/designer_plugin.md`, `docs/strip_chart.md`, `docs/analysis_chart.md`, `docs/widgets.md` and `docs/gallery_images.md` keep only statements that the code, the CI or `docs/benchmarks.md` support, without emoji in the headings or marketing wording. Corrected: `theming.md` said the colours could be set via QML (there is no QML binding), gave `LinearGauge` a `dialColor` and a `needleColor` it does not have and said `textColor` draws the gauge ticks (`scaleColor` does); `designer_plugin.md` gave the plugin as `build/plugin/libQtIndustrialWidgetsPlugin.so` (it is `build/lib/QtIndustrialWidgetsPlugin.so`), `.dylib` on macOS (CMake's module suffix there is `.so`) and Qt Creator's own plugin folder as the place for Designer plugins; `strip_chart.md` said autoscale shrinks after 30 frames (it is 30 recomputations) and that allocations grow with visible NaN gaps (fixed by #8); `getting_started.md` listed compiler versions that no CI job builds with.
- **vcpkg port** (#66): `portfile.cmake` carries the SHA512 of the `v2.5.0` tag archive (the tagged commit still had the `v2.4.0` hash, since the hash can be computed only after the tag).
- **Conan: the dependencies are pinned by `conan.lock`** (#116). With an empty cache the version ranges resolved `freetype` to 2.15.0, for which ConanCenter has no prebuilt `qt/6.11.1`, `harfbuzz/12.3.0` and `fontconfig/2.15.0`: `conan create --build=missing` built Qt from source, and the CI job (`--build=never`) passed only with a warm cache. `conan.lock` pins `freetype/2.14.3` and the rest for Linux, Windows and macOS; `docs/getting_started.md` (method 5) passes it.

### Tests
- **Workflows linted** (#138): an `actionlint (workflows)` job in `ci.yml` (every pull request and push to `main`) runs actionlint 1.7.12 with shellcheck 0.11.0, both at fixed versions with checked SHA-256, on every workflow; its 10 findings in `ci.yml` and `packaging.yml` (unquoted `HEAD^{tree}` and triplets, `ls` in the gallery image checks) are fixed, with no rule disabled.
- **Linux release packages checked** (#133): a `deb` job in its own workflow, `linux-packages.yml` (#136; every pull request and push to `main`, with no `paths` filter, and once a week), builds the `.deb` and the `.tar.gz` with the script `release.yml` uses, builds and runs `test_package` against the extracted `.tar.gz` (`CMAKE_PREFIX_PATH`), checks that Qt Designer loads the `.tar.gz`'s plugin with `QT_PLUGIN_PATH`, then installs the `.deb` with apt and fails unless the real Qt Designer (offscreen, `QT_DEBUG_PLUGINS=1`, no `QT_PLUGIN_PATH`) loads the plugin, the plugin's run path does not name `/usr/local`, and `test_package` builds and runs against the installed package.
- **`installed_designer_plugin`** (#127): installs the build into a temporary prefix and loads the installed Designer plugin with `QPluginLoader`, as Qt Designer does, with no library search path in the environment, then creates every widget it offers. It runs where the plugin is built, except on Windows; the CI now builds the plugin on macOS too, and the Linux and macOS jobs fail if the plugin is not built.
- **`citation_version`** (#130): a `ctest` test (CMake script, no extra dependency) fails when the `version` of `CITATION.cff` differs from the `project()` version in `CMakeLists.txt`, so a release cannot leave the citation behind.
- **One test-access class for StripChart** (#122), as for AnalysisChart: `internal::StripChartTestAccess` in `src/internal/StripChartTestAccess.h` (not installed). `StripChart.h` no longer declares and befriends the second class `QtIndustrialWidgets::StripChartTestAccess`, which was defined only in `tests/`; the friend declarations in `StripChart.h` and `AnalysisChart.h` are marked as test-only. No exported symbol changes.
- **vcpkg binary cache of the packaging workflow** (#119): the cache entry keeps only the binaries the run installed (read from `vcpkg_installed/vcpkg/status`; `qtindustrialwidgets` is left out, as it is rebuilt from the checkout in every run), so it no longer grows with every change of the port (the Windows static entry had reached 691 MiB; it is now 345 MiB). It is saved, under a key of its own, whenever its binaries differ from the restored ones: before, an exact hit of the key skipped the save, so binaries rebuilt for a reason the key does not cover (compiler, tools, triplet) were rebuilt again in every run.
- **Packaging on Windows and macOS** (#66): the `vcpkg`, `vcpkg registry` and `Conan` jobs of `packaging.yml` run on Ubuntu 24.04, Windows Server 2022 (MSVC 2022; vcpkg with a static and a dynamic triplet) and macOS 15 (Apple Clang, arm64). vcpkg's `qtbase` is built with `freetype` on every system, since Qt builds its offscreen platform plugin only with it; the consumer's configuration fails if a static Qt has no offscreen plugin to link, instead of building an executable that cannot start. On Windows vcpkg uses its own PowerShell (`VCPKG_FORCE_DOWNLOADED_BINARIES`): the PowerShell version is an ABI input of every package, and the runner image's changes with each image update, so the binary cache was not reusable on the next image. The jobs print the ABI inputs of one package (`zlib`), to explain a future cache miss.
- **Conan job from an empty cache** (#116): `packaging.yml` takes `conan-cache=skip` on `workflow_dispatch`; the cache key depends on `conan.lock`, without a restore key, so a new lockfile is checked from an empty cache.
- **The vcpkg registry checked in CI** (#113): a `vcpkg registry` job in `packaging.yml` (Linux, `x64-linux-release`) installs `qtindustrialwidgets` from the registry's current `HEAD`, with Qt from vcpkg's builtin registry, and runs the consumer in `test_package/`. The consumer prints the package version and, given `QIW_EXPECTED_VERSION`, fails when it differs: the job passes the latest GitHub release, so it fails while the registry is behind it.

## [2.5.0] - 2026-10-23

### Added
- **Static library build** (#107): the library follows `BUILD_SHARED_LIBS` and is still **shared when it is not set**. `-DBUILD_SHARED_LIBS=OFF`, or a project that sets it before adding the library with `FetchContent`, builds a static `libQtIndustrialWidgets.a`. In a static build the `QtIndustrialWidgets::QtIndustrialWidgets` target gives its consumers the public definition `QTINDUSTRIALWIDGETS_STATIC`, which empties `QTINDUSTRIALWIDGETS_EXPORT` (`qtindustrialwidgets_global.h`). A static library is needed with a static Qt (vcpkg's static triplets, ConanCenter's default `qt`): a shared library built against a static Qt carries its own copy of Qt. The Qt Designer plugin works with both builds.

### Changed
- **Conan recipe** (#66): the package is **static by default** (`shared=False`, was `True`), like ConanCenter's `qt`, which is static by default. The recipe now declares its Qt dependency (`qt/[>=6.2 <7]`, from ConanCenter), exports the library sources so `conan create` works from the repository, and gives consumers the same package and target names as the installed CMake config (`find_package(QtIndustrialWidgets)`, `QtIndustrialWidgets::QtIndustrialWidgets`) and, when static, the definition `QTINDUSTRIALWIDGETS_STATIC`. `shared=True` with a static Qt is refused by `validate()`: such a library would carry its own copy of Qt.
- **`docs/getting_started.md`, methods 4 and 5** (#66): vcpkg with a triplet (manifest and classic mode), Conan with `conan create` and `shared=False`, and a note on linking the platform plugin of a static Qt.

### Fixed
- **vcpkg port** (#66): `portfile.cmake` carries the SHA512 of the `v2.4.0` tag archive (the tagged commit still had the `v2.3.0` hash, since the hash can be computed only after the tag). Not verified with `vcpkg install`; the port remains experimental.
- **vcpkg port** (#66): it asks for `qtbase` without its default features (only `gui` and `widgets`), and moves the installed CMake config files from `lib/cmake` to `share/QtIndustrialWidgets` (`vcpkg_cmake_config_fixup(... CONFIG_PATH lib/cmake/QtIndustrialWidgets)`), which removes vcpkg's two post-build warnings. The `v2.4.0` port does not work with vcpkg's static triplets (the library was always shared, #107).

### Performance
- **AnalysisChart reuses its decimation buffers between frames** (#97). Every frame used to re-allocate, for every channel, its buckets, its segments and the polygon it draws, so the heap allocations per frame grew with the number of segments (non-finite samples and time gaps). The buffers are now kept between frames and channels, and the number of allocations per frame no longer depends on the number of segments. Rendered frames are unchanged, byte for byte.

### Tests
- **Packaging checked in CI** (#66): `.github/workflows/packaging.yml` (Linux only for now) installs the vcpkg port (`x64-linux-release`, Qt built by vcpkg and kept in a binary cache) and creates the Conan package (Qt from ConanCenter); in both, the consumer in `test_package/` finds the package with `find_package(QtIndustrialWidgets)`, renders a `LedIndicator` offscreen and checks the colour of its centre, lit and unlit. The vcpkg job builds a temporary copy of the port that uses the checked-out sources; started by hand with `port=released`, it uses the port as it is (release archive and SHA512), which is how the port of a release is checked once its hash is set. It runs twice a week, on demand and on changes to the packaging files.
- **AnalysisChart heap allocations per frame** (#97): `tst_AnalysisChartAllocations` (Linux only, as `tst_StripChartAllocations`) checks that the fewest allocations of a steady-state render are the same with 0, 10 and 100 non-finite samples or time gaps per channel. `tst_AnalysisPyramidAllocations` (all platforms) checks that a second `buckets()` and `segmentsFromBuckets()` into the same buffers allocate nothing.
- **`docs/images` checked in CI** (#103): the Linux job installs the Ubuntu font that the gallery's style sheet asks for, exports the gallery and fails when an image in `docs/images` differs byte for byte from the export, listing the images and the command that regenerates them. #95 had changed four images without re-exporting them; they were found only at the v2.4.0 release.

- **Decimated traces are drawn as one vertical stroke per column** (#73), in `StripChart` and `AnalysisChart`. Before, each device column was drawn as the polyline first → min → max → last, which strokes the column's extent twice. Now it is drawn as one vertical line from its minimum to its maximum, plus the connection from its last vertex to the first vertex of the next column. The end pixels of these lines are drawn explicitly. Visible difference: a column can light **at most one more row at either end of its extent** than before (approved in #73). No pixel is lit away from the trace, columns with a non-finite sample stay blank, and one bucket still maps to one device column.
- **Benchmark report regenerated** (#18): `docs/benchmarks.md` now comes from one session on the current code: 5 runs of `bench_StripChart` and 5 of `bench_AnalysisChart`, alternated, pinned to the performance cores and merged with `benchmarks/merge_runs.py`, with every run published. Results of its *Targets* table, unchanged targets, PASS only if met in all 5 runs:

  - **#6**, growth ≤ 25 % from 100k to 4M samples: **PASS** in Time and in SampleIndex. It is measured on a new interleaved 1 ch × 100k / 1 ch × 4M case in `bench_StripChart`.
  - **`addSample`** with autoscale ON ≤ 1 µs: **PASS**.
  - **#25**, AnalysisChart ≤ 16.7 ms at p95: **FAIL**, 1 of 7 cases passes.
  `docs/analysis_chart.md` quotes the new AnalysisChart figures.

### Fixed
- **Images on GitHub Pages** (#80): the images of the README main page and of `docs/widgets.md` returned 404 because Doxygen did not copy `docs/images/`; the `docs` target now copies them next to the HTML pages.
- **vcpkg port** (#66): `portfile.cmake` carries the SHA512 of the `v2.3.0` tag archive (the tagged commit still had the `v2.2.0` hash, since the hash can be computed only after the tag). ### Performance
- **StripChart reuses its decimated segment buffers between frames** (#8). Each frame used to free and re-allocate the buffer of every segment of every channel, so the heap allocations per frame grew with the number of visible gaps (non-finite samples). The buffers are now kept between frames and channels, and the number of allocations per frame no longer depends on the number of visible gaps. One bounded cost remains: the clip of the glow dot around a dropout next to it (#11), limited by the glow's radius. Rendered frames are unchanged, byte for byte.
- **AnalysisChart redraw with the one-stroke-per-column drawing** (#73). Measured in one session of 5 alternating runs per variant, published in `docs/benchmarks.md`, section *One vertical stroke per column (#73)*; #18 will regenerate all the tables there.
  - **Full view, 4 × 10 M samples:** median 52.49 → 39.39 ms (**−25 %**), p95 57.12 → 43.89 ms. The case still misses the 16.7 ms target of #25.
  - **Pan at 1/100 of the record:** median 9.15 → 11.35 ms (**+24 %**), p95 9.76 → 11.96 ms. Its p95 stays below 16.7 ms in all 5 runs (at most 12.44 ms).
  - StripChart was measured in the same way on #73. For the case of #5 (4 ch × 1M noisy) the result is not conclusive, because this machine's timings are bimodal.

### Tests
- **Heap allocations per frame** (#8), counted with a replacement `operator new` (`tests/AllocationCounter.h`):
  - `tst_M4DecimatorAllocations`, on all platforms: a second segment extraction into the same buffers allocates nothing;
  - `tst_StripChartAllocations`, on Linux only, because only ELF binding lets the counter see the library's allocations: the fewest allocations of a steady-state render are the same with 0, 10 and 100 visible gaps, and with a gap next to the glow plus 0, 10 and 100 elsewhere;
  - an all-NaN channel drawn after a channel with 100 gaps draws nothing.
- **`benchmarks/merge_runs.py`** (#18) also checks that the trace pixels of the 100k / 4M growth table (`Trace px 100k`, `Trace px 4M`) are equal in every run. Its tests cover the merged growth table and the rejection of runs with different pixels.
- **`tst_M4Decimator::columnStrokeStaysWithinPolylineExtent`** (#73) draws two `bench_StripChart` signals (SmoothSine, SpikesAndNaN; 10k samples) at DPR 1 and 2, both with the previous polyline and with the new drawing, and compares them column by column. The new drawing must light the same columns, no pixel more than one row beyond the polyline's extent, and no isolated pixel. The square-cap prototype of #73, which lit pixels detached from the trace, fails it.
- **`tst_M4Decimator::drawnColumnExtent`** (#90) replaces `pixelEquivalence` and its four `QEXPECT_FAIL`s. The decimated trace is drawn with StripChart's own drawing code (now in `src/internal/DecimatedTrace.h`, shared by the Time and SampleIndex paths; renders unchanged). In every device column it must light the vertical extent expected from the raw samples: their minimum and maximum, plus the half connections to the adjacent columns. The only tolerance is one row, from Qt's documented pixel model for aliased drawing. Columns with a non-finite sample must stay blank, and the rows where the raw drawing shows a column's minimum and maximum must be lit too.
- **CI job with Qt 6.2 LTS** (#79): `Linux (Ubuntu 24.04, GCC, Qt 6.2.4)` builds the library, the tests, the gallery and the Designer plugin against Qt 6.2.4 (installed with `install-qt-action`) and runs the full `ctest` at the four device pixel ratios, so the oldest supported Qt is built and tested on every pull request.
- **`tst_Compass::mouseInteractionBug`** (#79): the drag of the heading bug is sent as explicit mouse events with their buttons. With Qt 6.2, `QTest::mouseMove()` delivers no move event to an offscreen widget, so the test failed there at every device pixel ratio; the assertions are unchanged.

## [2.3.0] - 2026-10-18

### Added
- **`AnalysisChart` widget, phase 1 part 1** (#25): offline review of recorded multi-channel data (`qiw::AnalysisChart`). Channels with stable ids; `setChannelData()` copies absolute `std::chrono::nanoseconds` timestamps and `double` values per channel (different or irregular rates allowed), rejects decreasing timestamps (the previous data is kept, `false` and a warning), and `0` samples clears the channel; `clear()` empties the data and `removeAllChannels()` removes the channels. One shared Y axis; programmatic view (`setXRange()` clamped between a few samples of the densest visible channel and the data extent, at most one view width outside the data; `setYRange()`; `resetView()` with StripChart's 10 % autoscale margin); `nearestSample()`. Traces follow StripChart's rules, so the same data looks the same in both: a non-finite value or a time gap above `gapThreshold()` (default: 4 × the EMA of the sampling interval) breaks the trace. Time axis Relative (elapsed since the data start) or Absolute (`timeOrigin()` + t), value axis, legend, Designer plugin entry and a gallery showcase. Decimation: see part 3 below.
- **`AnalysisChart` phase 1 part 2: interaction, cursors and readout band** (#25). Mouse and keyboard navigation (the widget takes focus, `Qt::StrongFocus`): left drag pans X and Y; Shift + left drag or right drag zooms to a box (a box under 4 logical px is ignored); the wheel zooms X by ×1.25 per notch around the pointer, Ctrl + wheel zooms Y; double-click and Home reset the view; `+` / `-` zoom X around the centre; ← / → pan X and ↑ / ↓ pan Y by 10 % of the view. Two vertical cursors `Cursor::A` and `Cursor::B`, hidden until `setCursorVisible()`, placed at 1/3 and 2/3 of the view when the first data is loaded; a left drag that starts within 4 logical px of a visible cursor moves it instead of panning. `cursorPosition()` / `setCursorPosition()`, `cursorReadout()` (the nearest sample, no interpolation; none when the cursor is hidden or outside the channel's data), `cursorDeltaTime()` (t_B − t_A of the cursor positions), `cursorDeltaValue()`, `cursorColor`, `readoutVisible` and the `cursorsChanged()` signal. A readout band below the time axis shows the cursor times, Δt and, per visible channel, y_A, y_B and Δy (`---` when missing or non-finite), in the time unit of a nominal 10-tick axis over the view and with one decimal more than a 10-tick value axis, so its texts do not depend on the widget size. It lists at most 6 channels; further visible channels are summarised in a last row (`+N more`). The band is part of `minimumSizeHint()`: from that size up all of it is inside the widget.

## [2.1.0] - 2026-10-10

### Changed
- **Cosmetic 1-device-pixel decimated traces**: Decimated waveforms are now rendered with a cosmetic 1-device-pixel pen without antialiasing (`Qt::FlatCap`, `Qt::MiterJoin`). This eliminates `QStroker` outline polygon synthesis across dense M4 zig-zags.
- **Auto decimation threshold**: `DecimationMode::Auto` threshold adjusted from `2 · W_dev` to `W_dev` (plot area width in device pixels), ensuring raw rendering is used whenever sample count $\le W_{dev}$.
- **`yRangeChanged` emission timing**: Autoscale recomputation is now lazy. Signal `yRangeChanged(double, double)` is no longer emitted synchronously inside sample insertion methods (`addDataPoint`, `addSample`, etc.); it is emitted only during frame paint (`paintEvent`) or explicit programmatic queries (`yMinimum()`, `yMaximum()`).
- **Autoscale hysteresis**: Dynamic Y autoscale now applies hysteresis (`kAutoScaleMargin = 0.10`, `kAutoScaleShrinkThreshold = 0.50`, `kAutoScaleShrinkHysteresisCount = 30`). Range expands immediately on data spikes; range shrinking is deferred until the data span remains below 50% of the current range for 30 consecutive recomputations, completely eliminating cached grid redraw churn.

### Performance
- **$O(W)$ steady-state rendering**: Wired incremental M4 streaming (`M4Decimator::IncrementalStream`) directly into sample ingestion with cached `GeometryKey` validation and circular buffer eviction handling. Reusable scratch buffers in the private d-pointer avoid per-frame allocations proportional to the number of samples for continuous signals (with NaN gaps, allocations grow with the number of visible gaps).
- **Ingestion throughput**: Removed synchronous $O(N)$ full-buffer scanning from all six sample insertion APIs, marking autoscale dirty in $O(1)$.
- **Benchmarks**: see [`docs/benchmarks.md`](docs/benchmarks.md) (figures corrected after release, see Unreleased).

### Fixed
- **Documentation claims**: Corrected performance claims to reflect measured benchmark results, clarified that peaks are never lost while intra-pixel waveform shape is not preserved, and documented the 1-device-pixel cosmetic pen design.

### Fixed
- **SampleIndex decimation dropping recent samples**: Fixed integer floor division and missing bucket coverage in `computeIndexBuckets` that caused the most recent samples (up to 20% of the buffer) to never be drawn in decimated SampleIndex mode.
- **Time mode bucket boundary spike drop**: Fixed `computeTimeWindow` boundary formula where `tLatest == tEnd` excluded the leading sample point landing on bucket boundaries from decimation and window coverage checks.
- **Axis mode switching timestamp incompatibility**: Fixed channel buffer poisoning when switching between `Time` and `SampleIndex` modes or calling explicit-timestamp APIs in `SampleIndex` mode.

### Changed
- **Axis mode reset**: `setXAxisMode()` now clears all channel sample buffers when the mode changes to prevent mixing incompatible timebases, while preserving channel configuration metadata and `rejectedSampleCount()`.
- **Ignored timestamps in SampleIndex mode**: Explicit-timestamp insertion APIs (`addSample()`, `addSamples()`, `addUniformSamples()`, `addSynchronousSamples()`) in `SampleIndex` mode now record samples sequentially using the channel's running sample index (`totalSamples`), ignoring supplied timestamps and logging a one-time diagnostic warning per channel.

## [2.0.0] - 2026-10-10

### Breaking Changes & Migration from 1.x
- **Namespace encapsulation**: All widgets are now encapsulated inside `namespace QtIndustrialWidgets` (aliased as `namespace qiw`). The legacy `Q` prefix has been removed from widget class names (`RadialGauge`, `LinearGauge`, `SevenSegmentDisplay`, `LedIndicator`, `IndustrialKnob`, `StripChart`, `IndustrialSwitch`, `LevelMeter`, `AnnunciatorPanel`, `Compass`).
- **Encapsulated Channel Storage**: The `channel(int)` accessor and public `struct ChannelInfo` have been removed from `StripChart`. Use the direct accessors instead:
  - `channelName(int channelId)`
  - `channelColor(int channelId)`
  - `isChannelVisible(int channelId)`
  - `channelPenWidth(int channelId)`
  - `channelSampleCount(int channelId)`
  - `channelLatestValue(int channelId)`
- **Symbol Visibility**: Shared library targets now build with `CXX_VISIBILITY_PRESET hidden` and `VISIBILITY_INLINES_HIDDEN ON` to protect private ABI boundaries.

### Added
- **Nanosecond Real-Time Axis (`StripChart`)**:
  - Full nanosecond precision using `std::chrono::nanoseconds` for acquisition timestamps.
  - Dual axis modes: `XAxisMode::Time` (real-time streaming) and `XAxisMode::SampleIndex` (legacy index-based scrolling).
  - Dynamic 1-2-5 decade tick progression for oscilloscope reticle grid.
  - Relative time labels (`-10 s … 0 s`) with automatic unit scaling (ns, µs, ms, s, min) and Absolute wall-clock time labels (`HH:mm:ss.zzz`) via `setTimeOrigin(const QDateTime &)`.
- **M4 Min/Max Pixel-Column Decimation (`StripChart`)**:
  - Zero-aliasing peak preservation engine ensuring transient spikes, anomalies, and extreme values are never lost at high sampling rates.
  - Bounded vertex generation ($\le 4 \cdot W_{dev}$ vertices per channel) rendered as contiguous polylines.
  - Trace shimmer prevention via window boundary quantization ($t_{end} = \lceil t_{latest} / \Delta t_{px} \rceil \cdot \Delta t_{px}$).
  - Automatic and manual decimation modes (`DecimationMode::Auto`, `DecimationMode::Always`, `DecimationMode::Off`).
- **High-Rate Sample Insertion API (`StripChart`)**:
  - High-throughput insertion methods: `addSample()`, `addSamples()`, `addUniformSamples()`, and `addSynchronousSamples()`.
  - GUI arrival time vs. acquisition time distinction for legacy `addDataPoint()` slot.
  - Strict monotonic timestamp validation with rate-limited diagnostics and `rejectedSampleCount()`.
- **Gap Detection & Fault Telemetry**:
  - Automatic inter-sample gap detection based on $4 \times \text{EMA}(\Delta t)$ moving average or explicit `gapThreshold()`.
  - Raw storage of NaN and $\pm\infty$ sensor dropouts without painter crashes or autoscale disruption.
  - Legend displays `---` when the latest value is non-finite.
- **Buffer Capacity Scaling**: Circular SOA storage clamped up to $2^{24}$ (16,777,216 samples/channel, 16 bytes/sample/channel).
- **Gallery Showcase**: New "⚡ High-Rate DAQ" tab streaming 100 kHz telemetry with synthetic glitches, noise, dropouts, and real-time paint duration benchmarks.
- **Documentation**: New [StripChart Architecture Guide](docs/strip_chart.md).

### Changed
- **Autoscale Optimization**: Lazy evaluation recalculates vertical Y range at most once per frame or synchronously on range read.
- **Bulk Signal Efficiency**: Bulk insertion methods emit `dataAdded()` once per call.

### Fixed
- **Autoscale Infinity Resilience**: Addressed regression where `+Inf` inputs could corrupt vertical scale bounds.
