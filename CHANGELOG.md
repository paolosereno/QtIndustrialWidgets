## [Unreleased]

### Added
- **Landing page on GitHub Pages** (#80): the site's root is a landing page (`docs/site/`) with the README's sentence, the gallery's dashboard image, the 12 widgets with their captions and links to their class documentation, the quick start and links to the repository and the releases. `tools/check_site.py` checks in CI that its links resolve and that its widgets, captions, images and `GIT_TAG` match the README.

### Changed
- Qt 5 support is not planned (#53).
- **Qt 6.2 is required by CMake** (#79): `CMakeLists.txt` asks for `find_package(Qt6 6.2 REQUIRED …)` instead of accepting any Qt 6 or Qt 5 (`find_package(QT NAMES Qt6 Qt5 …)` without a version), and the installed package configuration asks for the same (`find_dependency(Qt6 6.2 …)`). Configuring against an older Qt now stops with CMake's error (`Could not find a configuration file for package "Qt6" that is compatible with requested version "6.2"`, listing the version found); the Qt 5 path is removed (#53).
- **Documentation addresses on GitHub Pages** (#80): the Doxygen documentation moves from the site root to `/api/`. Every page of the previous layout keeps a redirect page at its old address (`noindex`), including the guide pages, whose names no longer contain the CI runner's path (`md_docs_2widgets.html` instead of `md__2home_2runner_2work_…_docs_2widgets.html`, via `STRIP_FROM_PATH`). A `#fragment` in an old address is not carried over by the redirect.
- **Pages deployment** (#80): a failed deployment now fails the CI run (`continue-on-error` removed from `deploy-pages`).
- **Decimated traces are drawn as one vertical stroke per column** (#73), in `StripChart` and `AnalysisChart`. Before, each device column was drawn as the polyline first → min → max → last, which strokes the column's extent twice. Now it is drawn as one vertical line from its minimum to its maximum, plus the connection from its last vertex to the first vertex of the next column. The end pixels of these lines are drawn explicitly. Visible difference: a column can light **at most one more row at either end of its extent** than before (approved in #73). No pixel is lit away from the trace, columns with a non-finite sample stay blank, and one bucket still maps to one device column.
- **Benchmark report regenerated** (#18): `docs/benchmarks.md` now comes from one session on the current code: 5 runs of `bench_StripChart` and 5 of `bench_AnalysisChart`, alternated, pinned to the performance cores and merged with `benchmarks/merge_runs.py`, with every run published. The note that the figures predated #11–#16 is removed. Sections from earlier sessions (2.0.1 baseline, profiles, the #73 comparison) remain, marked as historical. Results of its *Targets* table, unchanged targets, PASS only if met in all 5 runs:
  - **#5**, 4 ch × 1M `BroadbandNoise` ≤ 8 ms: **FAIL** in Time and in SampleIndex.
  - **#6**, growth ≤ 25 % from 100k to 4M samples: **PASS** in Time and in SampleIndex. It is measured on a new interleaved 1 ch × 100k / 1 ch × 4M case in `bench_StripChart`.
  - **`addSample`** with autoscale ON ≤ 1 µs: **PASS**.
  - **#25**, AnalysisChart ≤ 16.7 ms at p95: **FAIL**, 1 of 7 cases passes.
  `docs/analysis_chart.md` quotes the new AnalysisChart figures.

### Fixed
- **Images on GitHub Pages** (#80): the images of the README main page and of `docs/widgets.md` returned 404 because Doxygen did not copy `docs/images/`; the `docs` target now copies them next to the HTML pages.
- **vcpkg port** (#66): `portfile.cmake` carries the SHA512 of the `v2.3.0` tag archive (the tagged commit still had the `v2.2.0` hash, since the hash can be computed only after the tag). The archive no longer contains `.claude/` (#69). Not verified with `vcpkg install`; the port remains experimental.

### Performance
- **AnalysisChart redraw with the one-stroke-per-column drawing** (#73). Measured in one session of 5 alternating runs per variant, published in `docs/benchmarks.md`, section *One vertical stroke per column (#73)*; #18 will regenerate all the tables there.
  - **Full view, 4 × 10 M samples:** median 52.49 → 39.39 ms (**−25 %**), p95 57.12 → 43.89 ms. The case still misses the 16.7 ms target of #25.
  - **Pan at 1/100 of the record:** median 9.15 → 11.35 ms (**+24 %**), p95 9.76 → 11.96 ms. Its p95 stays below 16.7 ms in all 5 runs (at most 12.44 ms).
  - StripChart was measured in the same way on #73. For the case of #5 (4 ch × 1M noisy) the result is not conclusive, because this machine's timings are bimodal.

### Tests
- **`benchmarks/merge_runs.py`** (#18) also checks that the trace pixels of the 100k / 4M growth table (`Trace px 100k`, `Trace px 4M`) are equal in every run. Its tests cover the merged growth table and the rejection of runs with different pixels.
- **`tst_M4Decimator::columnStrokeStaysWithinPolylineExtent`** (#73) draws two `bench_StripChart` signals (SmoothSine, SpikesAndNaN; 10k samples) at DPR 1 and 2, both with the previous polyline and with the new drawing, and compares them column by column. The new drawing must light the same columns, no pixel more than one row beyond the polyline's extent, and no isolated pixel. The square-cap prototype of #73, which lit pixels detached from the trace, fails it.
- **`tst_M4Decimator::drawnColumnExtent`** (#90) replaces `pixelEquivalence` and its four `QEXPECT_FAIL`s. The decimated trace is drawn with StripChart's own drawing code (now in `src/internal/DecimatedTrace.h`, shared by the Time and SampleIndex paths; renders unchanged). In every device column it must light the vertical extent expected from the raw samples: their minimum and maximum, plus the half connections to the adjacent columns. The only tolerance is one row, from Qt's documented pixel model for aliased drawing. Columns with a non-finite sample must stay blank, and the rows where the raw drawing shows a column's minimum and maximum must be lit too.
- **CI job with Qt 6.2 LTS** (#79): `Linux (Ubuntu 24.04, GCC, Qt 6.2.4)` builds the library, the tests, the gallery and the Designer plugin against Qt 6.2.4 (installed with `install-qt-action`) and runs the full `ctest` at the four device pixel ratios, so the oldest supported Qt is built and tested on every pull request.
- **`tst_Compass::mouseInteractionBug`** (#79): the drag of the heading bug is sent as explicit mouse events with their buttons. With Qt 6.2, `QTest::mouseMove()` delivers no move event to an offscreen widget, so the test failed there at every device pixel ratio; the assertions are unchanged.

## [2.3.0] - 2026-10-18

### Added
- **`AnalysisChart` widget, phase 1 part 1** (#25): offline review of recorded multi-channel data (`qiw::AnalysisChart`). Channels with stable ids; `setChannelData()` copies absolute `std::chrono::nanoseconds` timestamps and `double` values per channel (different or irregular rates allowed), rejects decreasing timestamps (the previous data is kept, `false` and a warning), and `0` samples clears the channel; `clear()` empties the data and `removeAllChannels()` removes the channels. One shared Y axis; programmatic view (`setXRange()` clamped between a few samples of the densest visible channel and the data extent, at most one view width outside the data; `setYRange()`; `resetView()` with StripChart's 10 % autoscale margin); `nearestSample()`. Traces follow StripChart's rules, so the same data looks the same in both: a non-finite value or a time gap above `gapThreshold()` (default: 4 × the EMA of the sampling interval) breaks the trace. Time axis Relative (elapsed since the data start) or Absolute (`timeOrigin()` + t), value axis, legend, Designer plugin entry and a gallery showcase. Decimation: see part 3 below.
- **`AnalysisChart` phase 1 part 2: interaction, cursors and readout band** (#25). Mouse and keyboard navigation (the widget takes focus, `Qt::StrongFocus`): left drag pans X and Y; Shift + left drag or right drag zooms to a box (a box under 4 logical px is ignored); the wheel zooms X by ×1.25 per notch around the pointer, Ctrl + wheel zooms Y; double-click and Home reset the view; `+` / `-` zoom X around the centre; ← / → pan X and ↑ / ↓ pan Y by 10 % of the view. Two vertical cursors `Cursor::A` and `Cursor::B`, hidden until `setCursorVisible()`, placed at 1/3 and 2/3 of the view when the first data is loaded; a left drag that starts within 4 logical px of a visible cursor moves it instead of panning. `cursorPosition()` / `setCursorPosition()`, `cursorReadout()` (the nearest sample, no interpolation; none when the cursor is hidden or outside the channel's data), `cursorDeltaTime()` (t_B − t_A of the cursor positions), `cursorDeltaValue()`, `cursorColor`, `readoutVisible` and the `cursorsChanged()` signal. A readout band below the time axis shows the cursor times, Δt and, per visible channel, y_A, y_B and Δy (`---` when missing or non-finite), in the time unit of a nominal 10-tick axis over the view and with one decimal more than a 10-tick value axis, so its texts do not depend on the widget size. It lists at most 6 channels; further visible channels are summarised in a last row (`+N more`). The band is part of `minimumSizeHint()`: from that size up all of it is inside the widget.
- **`AnalysisChart` phase 1 part 3: decimation, performance, docs and gallery** (#25). `decimationMode` (`Off` / `Auto` / `Always`, as `StripChart::DecimationMode`; default `Auto`): a channel with more samples in the view than device columns of the plot is drawn M4-decimated with one bucket per device column, as `StripChart` draws it (first, minimum, maximum and last finite sample of each bucket; cosmetic 1-device-pixel pen without antialiasing; the column of a bucket holding a non-finite sample left blank; the same gap threshold). Buckets follow the view (`floor((t − xStart) · W_dev / span)`); the plot's edges are snapped to device pixels and traces, ticks and cursors share one device mapping at every device pixel ratio. `setChannelData()` builds a min/max pyramid (blocks of 64 samples, at most 2.125 bytes per sample on top of the 16 of the stored data) from which a redraw takes the buckets instead of reading every sample in the view. New `bench_AnalysisChart`; the #25 target (redraw after a zoom or pan step ≤ 16.7 ms for 4 channels × 10 M samples at a 1920 device px plot) is **not met**: 6 of 7 cases fail, e.g. the full view redraws in 42.07 ms (median) — tables, method and the profile of the cause in [docs/benchmarks.md](docs/benchmarks.md#analysischart-performance-benchmarks). New guide `docs/analysis_chart.md` (API, bindings, readout band, dropout rule, memory, performance), README and Designer list entries, and an "Analysis Chart" gallery tab with about 1 M generated samples (two channels at different rates, spikes, NaN dropouts, a recording gap) and controls for the cursors, the view, the decimation mode and the time label format.
- **`AnalysisChart` measured performance** (#25): the target of #25, a redraw after a zoom or pan step in at most 16.7 ms for 4 channels × 10 M samples at a 1920 device px plot, is **not met**. On the benchmark machine the full view of 4 × 10 M samples redraws in **42 ms** (median, 42.07 ms; 6 of the 7 measured cases fail). Most of the time goes into drawing the decimated M4 columns, each stroked twice; drawing one vertical stroke per column, in `StripChart` and `AnalysisChart`, is being measured in [#73](https://github.com/paolosereno/QtIndustrialWidgets/issues/73). Tables and method: [docs/benchmarks.md](docs/benchmarks.md#analysischart-performance-benchmarks).

### Fixed
- **vcpkg port** (#66): `portfile.cmake` carries the SHA512 of the `v2.2.0` tag archive instead of an all-zero placeholder (never set since 1.0.x), and `vcpkg.json` declares the host dependencies `vcpkg-cmake` and `vcpkg-cmake-config` that the portfile needs. Not verified with `vcpkg install`; the port remains experimental. An in-repo port can carry the hash of a tag only on `main` after the tag, not in the tagged commit.
- **Standalone Doxygen configuration**: `docs/Doxyfile` no longer states version 1.0.0; the version comes from `CMakeLists.txt` through `QIW_VERSION` (README). The README command now creates `build/docs` first (Doxygen creates only the last folder of the output path, so it failed on a fresh clone), and the obsolete `DOT_TRANSPARENT` tag is gone (#69).
- **Source archives** (#69): `.gitattributes` marks `.claude/` (Claude Code settings) `export-ignore`, so `git archive` and the GitHub release archives no longer contain it.
- **Designer plugin description of `StripChart`** (#69): the "60+ FPS performance" claim, not backed by a measurement, is replaced by a pointer to the measured paint times in `docs/benchmarks.md`.

## [2.2.0] - 2026-10-17

### Added
- **`CircularBargraph` widget**: High-contrast circular arc indicator composed of discrete curved LED segments (`qiw::CircularBargraph`). Supports progressive Bar mode and single-cursor Dot mode, configurable angular sweep (e.g. 180°, 270°, 360°) and segment resolution (16, 24, 32, 48 segments), 3-stage threshold color zones by segment position (Normal, Warning, Critical; each segment takes the zone containing its centre, unlit segments show a dimmed tint of their zone) with `warningThreshold <= errorThreshold` kept by the setters (a setter that would break the order moves the other threshold too), value state (`ValueState`: `Valid`, `Underrange`, `Overrange`, `Invalid`; `valueState` property and `valueStateChanged` signal; out-of-range shown at the bound with a blinking end segment and `<` / `>` readout, `NaN` shown as `Invalid` with readout `---`) and read-only `rawValue`, ballistic peak-hold with decaying falloff starting at the end of the hold, centered digital readout pod, full Qt property bindings, and Qt Designer plugin integration (#17).
- **`LedIndicator::textColor` property** (#45): `textColor()` / `setTextColor()` set the label colour like the `textColor` of the other widgets. The default (invalid colour) keeps following `QPalette::WindowText`, so existing code renders as before.

### Changed
- **Supported Qt versions in the documentation** (#53): README, `docs/getting_started.md` and the CMake comment now state Qt 6.2+ only; Qt 5.15 is not supported at the moment, since it is not built or tested in CI. The build configuration is unchanged.
- **Sensor dropouts in decimated traces**: A decimation bucket (pixel column) that contains any non-finite sample is no longer drawn: its column stays blank and the trace is broken on both sides, in both axis modes, in batch decimation and in the incremental stream. Previously the bucket's finite samples were drawn as an isolated stroke and the dropout could be invisible. As a consequence, finite samples in such a column, including peaks, are not drawn; autoscale still uses them.
- **Decimated traces aligned to device-pixel columns**: Every decimation bucket now covers exactly one device column, in both axis modes and at any device pixel ratio (including 1.25 and 1.5): buckets are assigned with exact integer arithmetic (`k = floor(t · W_dev / span)`, `k = floor(i · W_dev / capacity)`), the window holds exactly `W_dev` buckets, the plot's left edge is snapped to a device pixel boundary, and decimated vertices are drawn at the centre of their column with the end pixels of every segment drawn explicitly. Raw traces and absolute time ticks use the same window mapping. Rendered output of decimated and raw traces differs from previous versions by fractions of a pixel. In `SampleIndex` mode the window holds the `W_dev` newest buckets, so with a wrapped buffer the oldest partial bucket can fall out on the left, and raw samples are spaced by `capacity` rather than `capacity − 1` (the newest sample of a full buffer lies within one device pixel of the right edge).
- **Glow dot next to a dropout**: In decimated traces the glow dot on the latest point is no longer drawn when the newest bucket is blank (the legend still shows the latest value), and it is clipped so it never draws inside a blank dropout column.
- **`RadialGauge` digital display layout** (#43): the readout pod is no longer a fixed 0.68 r × 0.28 r box. It is narrowed so that it and the unit text keep max(2 px, 0.02 r) from every scale label; except in the case below, it is never wider than before. The value font is the largest size up to the previous 0.15 r at which the widest value of the range (minimum or maximum at the current precision) fits, down to max(8 px, scale label font). The pod stays at its previous height or moves below the end-of-arc labels, whichever allows the larger value font (the previous height on a tie). The value has precedence: if it does not fit at that size, the pod grows to hold it whole, even over a label. The scale radius and label font are unchanged. With the default 270° arc the pod is narrower on most gauges (e.g. 0–8000 at 300 px: 99.3 → 82.3 px), and the pod moves down where that keeps a larger value font (e.g. −1000…1000 and 0–100000 at 200 px).
- **`SevenSegmentDisplay::text()` for values that round to zero** (#46): with `decimalPlaces` ≥ 0, a negative value that rounds to zero now gives the same text as zero (e.g. −0.04 with 1 decimal: "0.0", previously "-0.0").
- **`IndustrialSwitch` layout of labels, LED and safety guard** (#44):
  - the position labels are placed around the safety guard (its shadow, lift tab and hinge brackets included), so the closed cover never covers them; the closed cover is drawn at 0.9 opacity;
  - the status LED sits left of the ON label (vertical) or above it (horizontal), with its glow clear of every text;
  - the open guard is drawn edge-on in free plate space (left of the switch, or below it and below the centre label) instead of rotated over the labels and out of the widget; a click on it closes the guard (previously a click in the top 15 px of the guard area);
  - where a label, the LED or the open guard would not fit, the switch is drawn smaller about its centre.
- **`IndustrialSwitch::minimumSizeHint()` from the real font metrics** (#44): the smallest size (aspect ratio of the previous 50×80 / 80×50, not smaller) at which every label is drawn whole inside the plate and nothing covers it, computed from the widget font (glyph ink included), the safety guard, the number of positions and the texts. From this size up no label is clipped or covered; below it the LED and the guard still never cover a label, but labels may be clipped. Layouts no longer squeeze a switch below it (e.g. the gallery's Manual Controls tab).
- **`IndustrialSwitch::sizeHint()`** (#44): never smaller than `minimumSizeHint()`; with a safety guard and 3 positions, the smallest size with the aspect ratio of the previous hint (75×125 / 125×75) at which the switch keeps its natural size and every text fits.
- **`LevelMeter` scale layout from the real label widths** (#40): the room for the scale labels is computed from the ink width of the widest label in the scale font (widget font × 0.7, at least 6 pt) instead of fixed sizes. Vertical meters reserve max(36 px, room for the widest label), so meters whose labels fit the previous 36 px keep their layout (e.g. the default dB scale). Horizontal meters inset the bars at both ends so the first and last labels are whole inside the chassis; the bars are shorter by that amount.
- **`LevelMeter::minimumSizeHint()` from the real font metrics** (#40): from this size up every scale label is drawn whole and, on a horizontal linear scale, neighbouring labels do not overlap. The previous fixed 45 px width of a vertical meter was narrower than the chassis margins, the bars and the 36 px scale together (the bars were drawn partly outside the widget), so the vertical minimum is now larger (e.g. 74 × 100 instead of 45 × 100 for 2 channels, −60…+6 dB, default font). Horizontal linear meters get a wider minimum when their labels are wide (e.g. 0–100000). Size hints are updated when the range, the unit or the channel labels change.
- **`LevelMeter::sizeHint()`** (#40): never smaller than `minimumSizeHint()`; a vertical meter's scale term grows with the widest label.
- **`RadialGauge` draws only every k-th scale label when labels would be too close** (#50): previously a label was drawn at every major tick, so wide values overlapped near the top of the arc (e.g. "4000000" and "5000000" at 200 px). Now k is the smallest divisor of `majorTicks` for which every pair of drawn labels keeps max(4 px, 0.5 × label font height) between their boxes (the `LinearGauge` rule of #31); if none fits, only the first and last labels are drawn. On a span of 360° or more, where the last label lies on the first, the last one is not drawn. All ticks are still drawn and the label font is unchanged; with wide values fewer labels are shown (e.g. 0 / 2000000 / … / 10000000 at 200 px). The digital display is laid out against the drawn labels only, so on such gauges it can be larger or placed lower than before.
- **`LevelMeter` draws only the scale labels that keep a minimum gap** (#57): every tick is still drawn, but a label only if it keeps max(4 px, 0.5 × scale font height) from every other drawn label (the rule of #31 and #50); the first and last labels are always drawn (only the first when they clash). Linear scale: every k-th label, k the smallest divisor of 6 that keeps the gap. dB ladder: labels taken in priority order (the ends, 0 dB, −20, −6, −40, −12, −30, −3, +3), each only if it keeps the gap from those already taken. Small meters show fewer labels; e.g. the gallery's stereo dB meter no longer shows −3 and +3.
- **`LevelMeter` unit placement** (#57): on a vertical meter with a unit, a band above the bars holds the unit above the top label (the bars are shorter by that band; meters without a unit are unchanged); on a horizontal meter the unit moves right of the last label when the bars are too thin for it to clear the ticks, and the bars leave room for it inside the chassis.
- **`LevelMeter::minimumSizeHint()` of a horizontal meter** (#57): the height covers the margins, the title, the bars at 6 px each and the scale (from the scale font, 36 px at least) instead of a fixed 45 px (e.g. 64 px for 1 channel, 74 px for 2, 112 px for 4 with a title); the width keeps max(4 px, 0.5 × scale font height) between linear labels instead of 4 px, so all linear labels are drawn at the minimum (e.g. 0–100000: 257 → 261 px at 9 pt, 354 → 372 px at 13 pt), and on a dB scale it keeps the same gap between the two end labels, so both are drawn at the minimum (e.g. −60…+6 dB with unit "dB": 100 → 129 px at 20 pt; unchanged with the default font). Horizontal scale labels are centred in a rectangle as tall as the scale font line when it exceeds 14 px, so large fonts no longer draw labels over the ticks.

- **Cached scale and axis labels follow the widget font** (#51): `RadialGauge`, `LinearGauge`, `IndustrialKnob` and `StripChart` drew the text of their static cache with the application font, ignoring `setFont()` and style sheets (their value readouts already used the widget font). They now take family, weight, style and spacing from the widget font; the pixel size is unchanged. Widgets whose font comes from a style sheet change appearance, e.g. the gallery theme's `font-family` now applies to the scale labels too (with the narrower font the gallery's horizontal `LinearGauge` shows 0 / 50 / … / 250 instead of 0 / 125 / 250).
- **`LevelMeter::minimumSizeHint()` of a vertical meter** (#51): the height holds bars long enough that every linear label and both dB end labels keep max(4 px, 0.5 × scale font height) from each other, with the title, the unit band and the channel labels, instead of a fixed 100 px (never less than 100 px; e.g. 0–100: 122 px at 9 pt, 164 px at 13 pt; −60…+6 dB unchanged).

- **Text sizes and the widget font size** (#51): `LinearGauge` and `StripChart` scale the text sizes they derive from their geometry by the ratio between the effective pixel sizes (`QFontInfo`) of the widget font and of the application font, so `setFont()` with a larger font (also via `setPixelSize()` or a style sheet) gives larger texts; `StripChart` also widens the room for its axis labels and legend (plot margins) and the spacing of its time ticks. With the application font the ratio is exactly 1 and nothing changes. `RadialGauge`, `IndustrialKnob`, `Compass` and `CircularBargraph` take only family, weight and style from the widget font; their text sizes still come from the geometry, until their layouts make room for larger text. `IndustrialSwitch` and `LevelMeter` already derive their text sizes from the widget font size.
- **`LinearGauge` scale label size** (#37 point 1, #51): the label font is the largest size between 8 px and the height-derived one (12 px at most) at which at least every other label is drawn; the height-derived one when no size achieves that. At its size hint (280×100) a horizontal 0–250 gauge now shows 0 / 50 / 100 / 150 / 200 / 250 at 10 px instead of 0 / 125 / 250 at 12 px (DejaVu Sans); gauges that already showed every other label are unchanged.

### Fixed
- **Font size ratio falls back to the requested size when no font can be resolved** (e.g. systems without installed fonts) (#51): the ratio between the widget font and the application font used by `LinearGauge` and `StripChart` was 1.0 there, so their texts did not follow the widget font size.
- **`setFont()` on a painted widget** (#51): `RadialGauge`, `LinearGauge`, `IndustrialKnob` and `StripChart` refreshed their cached background only on palette changes, and `IndustrialSwitch` and `LevelMeter` not at all, so a font change after the first paint left the old text until something else invalidated the cache. They now refresh it on `QEvent::FontChange` (`IndustrialSwitch` and `LevelMeter` gain a `changeEvent()` override, which also updates their size hints).
- **Relative time labels with a short span** (regression introduced in #12): with a time span shorter than `W_dev` ns the window is `W_dev` ns wide (1 ns buckets), but relative X-axis labels were still computed for the configured span, so they did not match the data (e.g. "−400 ns" at the left edge of a 1000 ns window). Relative labels now describe the effective window, like absolute labels.
- **Exact multiply/divide near `INT64_MIN`**: the internal `mulDivFloor()` saturated to `INT64_MIN` when an intermediate product fell below it although the exact result fits (e.g. a result of `INT64_MIN + 1`); overflow is now decided on the final result. Not reachable with the timestamps and sample indices the widget uses, but it violated the documented valid range of the bucket grid.
- **Dropouts and spikes confined to their own column**: Decimation buckets used to straddle device-pixel columns (bucket width `span / W_dev` rounded to whole ns, x mapped with the exact span; `ceil(capacity / W_dev)` samples per bucket in `SampleIndex` mode; plot left edge at a fractional device position at fractional scaling), so a blank dropout column could be covered by its neighbours and a single-sample spike could be drawn in a neighbouring column. Dropouts now always leave their own device column blank and single-sample spikes light exactly their own column.
- **Performance figures**: Re-measured all `StripChart` performance figures with a corrected benchmark method (5 warm-up + 30 measured renders with min/median/p95, a streaming case, real insertion call counts, test signals defined as functions of time so every sample count draws the same image, trace pixel counts, two runs with the range of the medians); `docs/benchmarks.md` is now the only source of performance figures, and README, `docs/strip_chart.md` and this changelog quote or link it.
- **Non-reproducible baseline**: Removed the earlier baseline column, the extrapolated `addSample` figure and every speed-up factor derived from them. The 2.0.1 comparison in `docs/benchmarks.md` was re-measured in the same session; it uses the previous benchmark generator, whose samples are identical to the current one at the 1M sample count used for the comparison.
- **Unverified claims**: Removed the "over 1,000×" rasterization claim and replaced "zero per-frame heap allocations" with what the benchmark measures (allocations per frame independent of the number of samples for continuous signals; growing with the number of visible NaN gaps).
- **Previous `Auto` threshold**: The 2.1.0 entry now states the correct previous `DecimationMode::Auto` threshold (`2 · W_dev`, not `W_dev / 2`).
- **`LinearGauge` scale labels no longer overlap** (#31): both orientations used to draw every major label centred on its tick, so labels ran together when the ticks were close (e.g. "100125150…" on a horizontal gauge at its size hint, a stacked block on a short vertical thermometer), and the last horizontal label was half hidden under the digital display. Now only every k-th major label is drawn, with k the smallest divisor of `majorTicks` that keeps at least max(4 px, 0.5 × font height) between drawn labels (the first and last labels are always drawn), and the first and last labels are kept inside the scale. All ticks are still drawn and the label font is unchanged; with little space fewer labels are shown (e.g. 0 / 125 / 250 for a 0–250 horizontal gauge at 280×100). Labels are also no longer clipped to their font bounding rectangle, which cut up to 1 px off horizontal labels on macOS.
- **`RadialGauge` and `IndustrialKnob` scale labels no longer clipped** (#35): each scale label was drawn into a rectangle exactly as large as its font bounding rectangle and clipped to it, which cut up to 1 px off labels on macOS (the same defect fixed in `LinearGauge` in #31). The labels are now drawn without clipping; their positions are unchanged.
- **`LevelMeter` scale labels no longer clipped** (#40): every scale label was drawn into a fixed 24 px rectangle and clipped to it, so wider labels were cut in both orientations (e.g. "10000" at 11 pt: 23 instead of 30 px), and at small widths the end labels of a horizontal meter were not whole. Labels are now drawn whole, in a rectangle as wide as the widest label, without clipping. On a dB scale neighbouring labels can still overlap (#57).
- **`LevelMeter` scale labels no longer overlap** (#57): on the dB ladder the labels near 0 dB overlapped at any size (e.g. +3/+6 by 3.5–15.5 device px at the horizontal `sizeHint()`), and linear labels overlapped on vertical meters at the 100 px minimum height (11–13 pt) and on horizontal meters below their minimum width. The unit no longer touches the top label (vertical) or the last label (horizontal), and at the horizontal `minimumSizeHint()` the bars and channel labels are no longer drawn partly outside the chassis (the fixed 45 px height did not hold them even with 1 channel).
- **`RadialGauge` end-of-arc labels hidden by the digital display** (#43): the pod was drawn over the corner of the last scale label (e.g. "8000"), and of the first one with a symmetric range (e.g. "−1000"), at every size with the default 270° arc. A value wider than the pod (e.g. "100000.0" at 200 px) was clipped at the pod edges; it is now always drawn whole.
- **No negative zero in the numeric texts** (#46): a negative value that rounds to zero at the displayed precision was shown with a sign ("-0.0", "-0"). All fixed-point texts now go through one internal function, so they show "0.0" / "0": `RadialGauge`, `IndustrialKnob` and `LinearGauge` scale labels and value readouts, `LevelMeter` scale labels, `SevenSegmentDisplay`, the `CircularBargraph` readout (including "<" / ">"), and the `StripChart` Y-axis labels, legend, and time labels in seconds (e.g. "-0.0 s" for a tick at −40 ms with explicit negative timestamps). Other values are formatted as before, including the rounding boundary (−0.05 with 1 decimal is still "-0.1").
- **`IndustrialSwitch` texts covered or clipped** (#44): the LED was drawn over the title or the ON label, the guard (closed or open) over the position labels, the open guard beyond the widget edge, and side labels were clipped by their rectangle ("AUT", "ARME"); with the guard closed some labels dropped to a contrast of 1.9:1 or were fully hidden. From `minimumSizeHint()` up, every label now reaches at least 4.5:1 with the guard closed.

### Performance
- **SampleIndex streaming without periodic stream rebuilds**: While data streamed in, the SampleIndex window alternated between `W_dev` and `W_dev + 1` buckets, which changed the decimation stream's ring size and forced a full O(N) rebuild of the stream on many frames (periodic 50–190 ms frames in #7; 14 rebuilds in 36 frames for 1 ch × 4M samples). Fixed as a side effect of the bucket/pixel-column alignment (#12): the window always holds `W_dev` buckets, so the stream is built once and then updated per sample. Measured with SampleIndex and Time interleaved in the same loop, the SampleIndex streaming render p95 is within 0.75–1.26× of Time mode for the cases of #7.

### Tests
- **Every test at every device pixel ratio**: `ctest` runs every test binary at `QT_SCALE_FACTOR` 1, 1.25, 1.5 and 2 (`<name>`, `<name>_dpr125`, `<name>_dpr150`, `<name>_hidpi`). The DPR-based `QSKIP`s are removed: `nonFiniteValuesBreakTheTrace` checks its raw and decimated gaps at every DPR, and the pixel part of `windowIsQuantisedAndScrollIsShiftInvariant` is covered by `scrollIsShiftInvariantAtAnyDpr`. Dropout tests place NaNs from the real bucket grid (buckets need not hold a whole number of samples, e.g. 666/667 at DPR 1.5). Added tests for bucket grids with more buckets than samples, for `mulDivFloor()` at the `qint64` limits and for short time spans; `BucketGrid::bucketOf()` asserts its valid range in debug builds.
- **Bucket/pixel-column alignment**: Added a geometry property test (random widths, device pixel ratios 1/1.25/1.5/2, fractional plot positions, positions near ±10¹⁸), exact mul/div and bucket-grid tests, scroll shift invariance at any DPR, dropout visibility at any position, single-sample spike confinement, raw/decimated continuity and segment end-column tests; new ctest entries `tst_StripChart_dpr125` and `tst_StripChart_dpr150` run them at fractional device pixel ratios. Added tests for single, edge, consecutive, streaming and evicted dropouts, for the glow dot next to a blank column and for autoscale with a blank column, and extended the incremental-equals-batch property test to compare the sets of drawn and blank buckets.
- **`RadialGauge` digital display** (#43): `scaleLabelsNotHiddenByDigitalDisplay` (no scale-label pixel changes when the display is shown; 4 sizes × 3 ranges × 2 arcs) and `valueTextInsideDigitalDisplay` (the value stays inside the pod with a margin, including a value that only fits by covering a label), `valueFontNotReducedWhenLoweringAvoidsIt`; new `tst_RadialGaugeLayout` for the scale geometry, pod layout, choice of the place with the larger value font, value precedence and value-font fitting.

## [2.1.0] - 2026-10-10

### Changed
- **Cosmetic 1-device-pixel decimated traces**: Decimated waveforms are now rendered with a cosmetic 1-device-pixel pen without antialiasing (`Qt::FlatCap`, `Qt::MiterJoin`). This eliminates `QStroker` outline polygon synthesis across dense M4 zig-zags.
- **Auto decimation threshold**: `DecimationMode::Auto` threshold adjusted from `2 · W_dev` to `W_dev` (plot area width in device pixels), ensuring raw rendering is used whenever sample count $\le W_{dev}$.
- **`yRangeChanged` emission timing**: Autoscale recomputation is now lazy. Signal `yRangeChanged(double, double)` is no longer emitted synchronously inside sample insertion methods (`addDataPoint`, `addSample`, etc.); it is emitted only during frame paint (`paintEvent`) or explicit programmatic queries (`yMinimum()`, `yMaximum()`).
- **Autoscale hysteresis**: Dynamic Y autoscale now applies hysteresis (`kAutoScaleMargin = 0.10`, `kAutoScaleShrinkThreshold = 0.50`, `kAutoScaleShrinkHysteresisCount = 30`). Range expands immediately on data spikes; range shrinking is deferred until the data span remains below 50% of the current range for 30 consecutive recomputations, completely eliminating cached grid redraw churn.

### Performance
- **$O(W)$ steady-state rendering**: Wired incremental M4 streaming (`M4Decimator::IncrementalStream`) directly into sample ingestion with cached `GeometryKey` validation and circular buffer eviction handling. Reusable scratch buffers in the private d-pointer avoid per-frame allocations proportional to the number of samples for continuous signals (with NaN gaps, allocations grow with the number of visible gaps).
- **Ingestion throughput**: Removed synchronous $O(N)$ full-buffer scanning from all six sample insertion APIs, marking autoscale dirty in $O(1)$.
- **Benchmarks**: see [`docs/benchmarks.md`](docs/benchmarks.md) (figures corrected after release, see Unreleased).

### Fixed
- **Documentation claims**: Corrected performance claims to reflect measured benchmark results, clarified that peaks are never lost while intra-pixel waveform shape is not preserved, and documented the 1-device-pixel cosmetic pen design.

## [2.0.1] - 2026-10-10

### Fixed
- **SampleIndex decimation dropping recent samples**: Fixed integer floor division and missing bucket coverage in `computeIndexBuckets` that caused the most recent samples (up to 20% of the buffer) to never be drawn in decimated SampleIndex mode.
- **Time mode bucket boundary spike drop**: Fixed `computeTimeWindow` boundary formula where `tLatest == tEnd` excluded the leading sample point landing on bucket boundaries from decimation and window coverage checks.
- **Axis mode switching timestamp incompatibility**: Fixed channel buffer poisoning when switching between `Time` and `SampleIndex` modes or calling explicit-timestamp APIs in `SampleIndex` mode.

### Changed
- **Axis mode reset**: `setXAxisMode()` now clears all channel sample buffers when the mode changes to prevent mixing incompatible timebases, while preserving channel configuration metadata and `rejectedSampleCount()`.
- **Ignored timestamps in SampleIndex mode**: Explicit-timestamp insertion APIs (`addSample()`, `addSamples()`, `addUniformSamples()`, `addSynchronousSamples()`) in `SampleIndex` mode now record samples sequentially using the channel's running sample index (`totalSamples`), ignoring supplied timestamps and logging a one-time diagnostic warning per channel.

## [2.0.0] - 2026-10-10

### Breaking Changes & Migration from 1.x
- **Namespace encapsulation**: All widgets are now encapsulated inside `namespace QtIndustrialWidgets` (aliased as `namespace qiw`). The legacy `Q` prefix has been removed from widget class names (`RadialGauge`, `LinearGauge`, `SevenSegmentDisplay`, `LedIndicator`, `IndustrialKnob`, `StripChart`, `IndustrialSwitch`, `LevelMeter`, `AnnunciatorPanel`, `Compass`).
- **Encapsulated Channel Storage**: The `channel(int)` accessor and public `struct ChannelInfo` have been removed from `StripChart`. Use the direct accessors instead:
  - `channelName(int channelId)`
  - `channelColor(int channelId)`
  - `isChannelVisible(int channelId)`
  - `channelPenWidth(int channelId)`
  - `channelSampleCount(int channelId)`
  - `channelLatestValue(int channelId)`
- **Symbol Visibility**: Shared library targets now build with `CXX_VISIBILITY_PRESET hidden` and `VISIBILITY_INLINES_HIDDEN ON` to protect private ABI boundaries.

### Added
- **Nanosecond Real-Time Axis (`StripChart`)**:
  - Full nanosecond precision using `std::chrono::nanoseconds` for acquisition timestamps.
  - Dual axis modes: `XAxisMode::Time` (real-time streaming) and `XAxisMode::SampleIndex` (legacy index-based scrolling).
  - Dynamic 1-2-5 decade tick progression for oscilloscope reticle grid.
  - Relative time labels (`-10 s … 0 s`) with automatic unit scaling (ns, µs, ms, s, min) and Absolute wall-clock time labels (`HH:mm:ss.zzz`) via `setTimeOrigin(const QDateTime &)`.
- **M4 Min/Max Pixel-Column Decimation (`StripChart`)**:
  - Zero-aliasing peak preservation engine ensuring transient spikes, anomalies, and extreme values are never lost at high sampling rates.
  - Bounded vertex generation ($\le 4 \cdot W_{dev}$ vertices per channel) rendered as contiguous polylines.
  - Trace shimmer prevention via window boundary quantization ($t_{end} = \lceil t_{latest} / \Delta t_{px} \rceil \cdot \Delta t_{px}$).
  - Automatic and manual decimation modes (`DecimationMode::Auto`, `DecimationMode::Always`, `DecimationMode::Off`).
- **High-Rate Sample Insertion API (`StripChart`)**:
  - High-throughput insertion methods: `addSample()`, `addSamples()`, `addUniformSamples()`, and `addSynchronousSamples()`.
  - GUI arrival time vs. acquisition time distinction for legacy `addDataPoint()` slot.
  - Strict monotonic timestamp validation with rate-limited diagnostics and `rejectedSampleCount()`.
- **Gap Detection & Fault Telemetry**:
  - Automatic inter-sample gap detection based on $4 \times \text{EMA}(\Delta t)$ moving average or explicit `gapThreshold()`.
  - Raw storage of NaN and $\pm\infty$ sensor dropouts without painter crashes or autoscale disruption.
  - Legend displays `---` when the latest value is non-finite.
- **Buffer Capacity Scaling**: Circular SOA storage clamped up to $2^{24}$ (16,777,216 samples/channel, 16 bytes/sample/channel).
- **Gallery Showcase**: New "⚡ High-Rate DAQ" tab streaming 100 kHz telemetry with synthetic glitches, noise, dropouts, and real-time paint duration benchmarks.
- **Documentation**: New [StripChart Architecture Guide](docs/strip_chart.md).

### Changed
- **Autoscale Optimization**: Lazy evaluation recalculates vertical Y range at most once per frame or synchronously on range read.
- **Bulk Signal Efficiency**: Bulk insertion methods emit `dataAdded()` once per call.

### Fixed
- **Autoscale Infinity Resilience**: Addressed regression where `+Inf` inputs could corrupt vertical scale bounds.
- **Trace Shimmer**: Eliminated pixel jitter while scrolling by anchoring bucket indices to absolute time.
