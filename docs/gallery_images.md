# Documentation images

The widget images in [`docs/images/`](images/) and the "Widgets" table of the README are generated by
the gallery executable, so they can be regenerated after any visual change with one command.

## Regenerate

```bash
cmake --build build --target QtIndustrialWidgetsGallery
./build/bin/QtIndustrialWidgetsGallery --export-gallery docs/images
```

Re-export after any change that alters what the gallery draws: **the CI fails when `docs/images` differs from the
export of the commit** (see *Checked in CI* below).

The committed images are exported on Linux (Ubuntu 24.04, Qt 6.4.2 from Ubuntu). The gallery's style sheet asks for
the fonts `'Segoe UI', 'Ubuntu', 'Helvetica Neue', sans-serif`, so the tab images need the **Ubuntu font**
(`sudo apt-get install fonts-ubuntu`); without it the tabs fall back to another font and differ. If your machine
cannot reproduce the images, take them from the CI instead: the `gallery-images` artifact of the pull request's run
holds the export of that commit (the dark images are the files without the `-light` suffix).

The export runs headless: when `QT_QPA_PLATFORM` is not set it uses the `offscreen` platform by itself. It prints one
line per written file and exits with:

| Exit code | Meaning |
|---|---|
| 0 | every image written |
| 1 | the output directory cannot be created, or at least one image failed (the error names the widget showcase or the gallery tab) |
| 2 | invalid command-line options |

## Options

```
QtIndustrialWidgetsGallery --export-gallery <output-dir> [--dpr 1|2] [--theme dark|light|both]
```

| Option | Default | Effect |
|---|---|---|
| `--export-gallery <output-dir>` | — | export instead of opening the window; the directory is created if needed |
| `--dpr 1\|2` | `2` | device pixel ratio of the images (sets `QT_SCALE_FACTOR` before the application starts) |
| `--theme dark\|light\|both` | `dark` | `light` and `both` also write the light variants, with a `-light` suffix |

Only the dark theme at DPR 2 is committed. CI exports both themes and uploads them as a workflow artifact
(`gallery-images`).

## What is exported

- **One image per widget showcase**, each widget rendered on its own at a fixed logical size (or at its `sizeHint()`) on the gallery's
  group-box colour: `<widget>-<variant>[-light].png`, e.g. `radial-gauge-warning.png`,
  `circular-bargraph-overrange.png`.
- **One image per gallery tab** at 1200×820: `tab-<name>[-light].png`, e.g. `tab-daq.png`.

## On GitHub Pages

The committed images are also the images of the [documentation site](https://paolosereno.github.io/QtIndustrialWidgets/):
the CMake `docs` target copies `docs/images/` into the Doxygen output, and the landing page (`docs/site/`, target
`site`) shows them. They are not copied anywhere else in the repository.

## Determinism

The same commit, platform and options give byte-identical files. The export:

- renders each showcase right after configuring it, **without running the event loop**, so no timer fires: LED and
  segment blinking, annunciator flashing, peak hold and decay stay in their initial state, and switches are not
  animated (`setAnimated(false)`);
- for the gallery tabs, does not start the simulation or the auto-tour, stops LED blinking, resets held peaks,
  disables the DAQ paint-time measurement, and only delivers posted events (layout, polish), never timer events;
- uses fixed analytic data only, with explicit timestamps for time-axis strip charts: no wall clock and no random
  numbers.

Check it by exporting twice and comparing the directories (`diff -r`).

**Fonts differ between platforms**, so images from different platforms (or from machines with different fonts) are
not expected to match. The committed images come from Linux with the Ubuntu font (see *Regenerate*); do not compare
images from other platforms with them.

## Checked in CI

The Linux job (`Linux (Ubuntu 24.04, GCC, Qt 6)`, with `fonts-ubuntu` installed) exports the gallery and compares
every image in `docs/images/` byte for byte with the export (#103). If any differs, the job fails, lists the images
and prints the command that regenerates them. The `gallery-images` artifact is uploaded before the check, so it is
available when the check fails.

## Add a showcase for a new widget

Every public widget needs at least one showcase: `tst_GalleryShowcases` reads the public headers in
`include/QtIndustrialWidgets/` and fails, naming the class, when a widget has none.

1. In `examples/gallery/Showcases.cpp`, write a factory that builds and configures the widget for a `Theme` (no
   parent, no event loop needed, fixed data only).
2. Add an entry to `showcases()`: widget class name, kebab-case variant, logical size and factory. A size of
   `QSize()` renders the widget at its own `sizeHint()`.
3. Rebuild, run `tst_GalleryShowcases`, regenerate the images and add the new PNG to the README table.
